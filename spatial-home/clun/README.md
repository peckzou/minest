# Clun — 7 South Drive, Wokingham · 三维建模（第一阶段）

Edwardian Arts & Crafts 住宅（约 1908–09）。独立展示场景：镜头绕建筑旋转，可掀屋顶、按层剖切看室内。
不改动 Spatial Home 现有任何环境；没有注入主应用页面，所以不需要重新生成 `index.html` / `iphone.html` 等。

## 运行

```bash
cd /Users/cece/Documents/minest-spatial-release && python3 -m http.server 8171
```

打开 `http://127.0.0.1:8171/spatial-home/clun/`。脚本有缓存，改后强制刷新。
地址参数：`?view=hero|eye|front|rear|south|north|aerial|top|rear-s|rear-n|front-s|section|sectionStair`、`&cut=1.5`（水平剖切标高，米）、`&sec=-3.0`（竖向剖面位置 X，`&secside=n` 留北半边）、`&cam=方位,仰角,距离,目标x,y,z`、`&hide=roof,chimneys`、`&mode=white`、`&auto=1`、`&ui=0`。
页面上「一层 / 二层 / 阁楼」做水平剖切，「剖面」沿南北方向切开看各层层高和阁楼斜顶，「楼梯剖面」沿楼梯井切开看楼梯。
操作：拖动旋转 · 滚轮 / 捏合缩放 · 右键或 Shift 拖动平移。地面上的红箭头指向工程坐标的 +X（北）。

## 约定

- 单位米。**+X 北、+Y 西、+Z 上**；原点 = 中央入口门洞中心、正立面外墙面、一楼完成面；主入口朝东（−Y）。
- 模型全部在工程坐标里建，最外层一个 Group 转成 three.js 的 Y 向上（`model.js`）。
- 所有未实测的尺寸集中在 `js/params.js` 的参数表里，带来源和可信度；页面里点「参数表」可以看。
  **没有任何一项是 VERIFIED**：平面图上标注的房间尺寸和面积记 STATED（PROVISIONAL），其余全是 ESTIMATED（plan = 平面图量取 / photo = 照片推算 / assumed = 假设）。

M3 的取舍（与平面图不一致或无法确定的地方）：
- **楼梯走向是按一楼平面图和梯下储物间的位置判断的**。二楼平面图上的 UP / DN 箭头和一楼、阁楼两张图互相矛盾，照它画不出一部能走通的楼梯，所以没有完全照抄。
- 阁楼楼梯到达处和平台前部在老虎窗下，净高只有约 1.5 m；一楼楼梯正面横跑上方净高约 1.9 m。原因是层高、檐口、老虎窗都是估算值，真实房子应该更高。
- 平面图上前门在门廊前沿（门后有一个约 1 m 深的小门厅），模型里前门还在主墙上、门廊敞开。没有改外观。
- 餐厅转角壁炉、起居室壁炉、厨房橱柜、卫浴洁具没做（属于室内装修，不在范围内）。一楼卫生间只做了一间，平面图上分成两小间。
- 隔墙厚度和门洞宽度统一取值（参数表 `wallSpine` / `wallInt` / `doorW` / `doorH`）。

### 插队：外景（`?scene=valley`，页面上「场景」按钮切换）
用户最后定的交付效果图（`art/delivery-plate.jpg`，2576×1438）整张做底图，最大程度保留原场景：树屋、小溪、木栈道、栅栏、石桌、花、村庄、教堂、雪山、瀑布全是原图。只把图里原来那栋房子换成 Clun，按高度缩到原房子的 75%。代码在 `js/plate.js`（绘画化在 `js/painterly.js`）。
- **抹掉原房子**：载入时在画布上处理。房顶上方的山向下镜像延伸，房身一带用它右边那条山林和村庄左右镜像拼接，两者之间渐变成带雾的山脚；门前的花丛和台阶不动。遮罩是低分辨率的房子轮廓，放大时边缘自然羽化。
- **放 Clun**：按底图的透视放（假定底图水平视角 60°，地平线在 65% 高处，由原房子的屋檐线和墙脚线汇聚估出）。门的底边对准原来的门（台阶从那里下去），朝向和原房子一样露出左侧山墙，离镜头的距离自动求出，让门底到烟囱顶的高度是原房子的 75%。卡通光照，脚下有接触阴影。
- **画风**：补好的底图做一遍绘画化（笔触、柔和配色），和 3D 房子统一。
- **镜头**：固定在底图的机位，只能推近（滚轮 / 捏合）和在底图范围内平移；竖屏时以房子为中心。

外景的问题：
- 补出来的房后山林和村庄是从旁边镜像拼的，细看能看出重复。
- 房子是卡通光照，底图是照片绘画化，两者质感还有差别。
- 底图的视角和地平线是估算的，房子的透视和原图可能有一两度的出入。
- 左侧烟囱后的山腰有一小块发白的补图痕迹（外屏近景里比较明显）。

### Duo 内外屏（外景）
- **外屏 = 近景**：以房子为中心、略推近，小人在门前小路上。**内屏 = 远景**：房子、村庄、小溪、雪山，瀑布在右边缘。
- **展开（外 → 内）**：从房子近景开始，停 0.5 秒后用 2.6 秒拉远到整片山谷，同时有一道柔光扫过，小人停下朝镜头挥手。**合上（内 → 外）**：1.6 秒推回房子。
- 判定：Duo 页面给 `<html>` 加 `duo-outer` / `duo-inner` 类时直接用；没有时只在触屏设备上按尺寸猜（窄长 = 外屏，接近方形 = 内屏），电脑窗口一律算普通。折叠时页面重载的话，用 sessionStorage 记住 8 秒内的上一屏，照样播过渡。真机 Duo 屏上隐藏标题卡和面板，只留画面。
- **电脑上预览**：面板「Duo 预览」的「外屏 / 内屏（展开）/ 关」把画面放进机身大小的框里，框的宽度和镜头一起变；也可以直接打开 `?scene=valley&sim=outer`。测试用 `?duo=outer|inner` 强制某一屏。
- 没在真机 Duo 上试过；真机上折叠时 WebView 是否重载、过渡是否流畅，需要装到设备上看。

### 未解决 / 待确认
1. **朝向有矛盾**。任务书（Historic England 转述）说正面朝东；但平面图上的指北针和 Google Earth 截图 GE_01 的罗盘都指示正面大致朝**西南**（厨房扩建在东南端、阳光房在北角）。
   模型按任务书约定建（正面 = −Y = “东”），几何不受影响，只影响方位名称和以后的日照方向。需要确认用哪个。
2. **Historic England 条目编号存疑**。参考包自带的 README 说 1392400 登记的是 78 Rose Street 而不是 Clun；我这边两种方式访问都是 403，无法判断。
3. 层高、檐口、屋脊标高都是照片推算（檐口距地约 5.6 m、屋脊约 9.25 m），误差可能有 ±0.3 m。
4. 厨房烟囱：照片里在屋脊与斜脊面交点附近（X≈9.1），平面图的烟囱垛却画在北外墙外侧。按照片放。

6. 阳光房平面图上画的是四坡，背面照片是朝西的玻璃山墙；按照片做。
7. 主屋顶两端按山墙端做；正面照片里屋顶两端略有内收，可能是很陡的半斜脊，M2 对照后再定。
