# Minest offline · V1 — audit and plan (2026-11-28)

Goal (the user): the Minest app works without a network for nearly everything. AI, cloud sync and links to outside
sites may wait for the network; the board, My World, Spatial Home, the worlds, the games, the pet, badges and the
study tools should not.

## 1 · What the app does today (audit)

- The iOS app loads a page **bundled in the app**: `ios/Minest/Minest/iphone18.0.html` (ipad.html on iPad), from
  `file://` (`ContentView.targetURL`, `MinestWebView.load`). Only that page, a few other pages, `vendor/`, one avatar
  model and `BadgeResources/` (38 MB) are in the bundle.
- Everything else comes from **minest-app.vercel.app**: 1,059 absolute URLs in the page (1,001 of them
  `public/anchor-charts/…`), and relative paths (`spatial-home/…`, the worlds, `badge-index/…`, `my-world-interiors/…`)
  that each feature rewrites to Vercel when the page runs from `file:` — about 15 different hand-written rewrites
  (`location.protocol === 'file:' ? 'https://minest-app.vercel.app/…' : '…'`).
- No `WKURLSchemeHandler`, no cache policy beyond the default, no service worker. Offline, every one of those requests
  fails.
- User data (boards, My World, routine, pet, badges…) lives in the page's storage — `localStorage` / IndexedDB of the
  `file://` origin — plus cloud copies (Firebase, the Minest server).

(no extension) are not listed. The final list of files comes from Phase 2's recorder, not from this scan.

## 2 · Plan

**One local origin that serves everything, cache first.** The app's page moves from `file://` to a custom scheme,
`minest://app/…`, served by a `WKURLSchemeHandler` in the app:

1. a file in the app bundle → served from the bundle;
2. else a file in the app's offline store (Application Support/Offline) → served from there;
3. else fetched from `https://minest-app.vercel.app/<same path>`, stored, served — so anything opened once online
   works offline afterwards;
4. offline and not stored → a clear 404 the page already handles.

Why this and not "bundle everything": the app stays small (core in the bundle, ~250 MB of content arrives on use or
by a "Download for offline" button), updates to content keep coming from Vercel, and the page needs almost no edits:
on `minest:` the 15 rewrites take their **non-`file:`** branch, i.e. relative paths, which the handler serves. The
1,059 absolute Vercel URLs are rewritten to `minest://app/` by the handler as it serves html / js / css (`api/…`
stays on the network).

Not possible the same way for https: WebKit does not let an app intercept `http(s)` requests, which is why the page
has to live on its own scheme.

### Phases

- **Phase 1 — the scheme and the cache (app).** `MinestSchemeHandler` (bundle → store → network-and-store),
  MIME types, range requests for audio / video, the Vercel → `minest://app/` rewrite for text, `api/` and other hosts
  untouched. ContentView loads `minest://app/iphone18.0.html`.
  **Data must come along:** the storage of the `file://` origin is not visible from `minest://app`. Before the first
  load on the new origin, a one-time migration reads the old origin's `localStorage` (and the durable stores'
  IndexedDB) in a hidden web view and writes it into the new one; the old data is not deleted, so the switch can be
  undone by going back to `file://`. This is the risky step and gets a build flag to switch back.
- **Phase 2 — the list.** A recorder in the handler logs every path served (debug builds); a guided walk through every
  page builds `offline-manifest.json` (exact list + sizes + hashes), checked in and regenerated by a script.
- **Phase 3 — Download for offline.** Settings › Offline: total size, "Download everything" / per-pack (Core, Worlds,
  Badges, Anchor charts, 3D models), progress, last update, "Remove downloads". Packs come from the manifest;
  downloads resume, and stored files are checked against the manifest's hashes.
- **Phase 4 — the page without network.** Every network feature says plainly that it is offline instead of spinning
  or failing silently: AI (board builder, chat, voice), cloud sync (queue, sync later — the durable stores already
  queue), Wikipedia pictures, outside links. An offline banner in the system Dock.
- **Phase 5 — the web.** The same idea for Safari / the home-screen app: a service worker on minest-app.vercel.app
  with the same manifest (cache first, packs on request).

Each phase ships on its own; Phase 1 alone already makes everything opened once work offline.

## 3 · Decisions for the user

1. Phase 1 changes the page's origin (`file://` → `minest://app`) and migrates the data; the old data stays on the
   device as a fallback. OK to go ahead?
2. What goes **inside the app bundle** (available offline from the first launch, makes the app bigger), what comes
   **on use or by download**? Suggested: core pages, Spatial Home, the badge wall and the board's anchor charts' thumbs
   inside (~60 MB); worlds, 3D interiors, full-size charts, models by download.
3. Which features may honestly say "needs a network": AI, cloud sync, voice, outside pictures and links (suggested).
